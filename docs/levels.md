# 贡献者等级

等级用于描述参与者已经展示的工程能力，作为任务选择与培养目标的依据。

| 等级 | 名称 | 能力与成果依据 |
| --- | --- | --- |
| L0 | 学习者（Learner） | 正在准备注册，学习 Git 与开源协作流程 |
| L1 | 见习贡献者（Apprentice） | 已完成 Fork、提交本人注册 PR，并成功合入 |
| L2 | 贡献者（Contributor） | 能够独立完成任务、提交符合上游要求的成果并处理评审意见 |
| L3 | 高级贡献者（Advanced Contributor） | 能够分析复杂问题、设计修改方案、评审贡献并指导其他参与者 |
| L4 | 维护者培养（Maintainer Track） | 能够持续承担模块维护、版本验证与社区协作职责 |

晋级条件按年度发布，参见 [2026 年晋级规则](../programs/2026/progression.md)。晋级记录保存所使用的年度规则版本和成果证据。

L0 → L1 由注册 PR 合入触发自动晋级，无需分配导师、导师签名或导师评估。维护者审核注册 PR，CI 核对本人 GitHub 身份及文件格式。Bot 记录注册 PR 和合入提交，直接更新个人 JSON 中的等级与晋级记录。

任务成果按照[贡献评估标准](assessment.md)验收。L2 → L3 和 L3 → L4 按年度规则执行人工审核，并通过晋级 PR 保存决定。参与者可以补充证据并申请复核。

L4 表示 Mission Forge Contributor Program（MFCP）内部培养阶段。上游项目的维护权限由对应社区决定。具体激励安排见[津贴与奖励](stipends.md)。

## 任务难度

任务难度表示完成任务需要展示的能力，使用以下全小写标签。贡献者等级依据持续表现评估，任务成果可以作为等级评估的证据。

| 难度 | 标签 | 任务要求 | 典型任务 |
| --- | --- | --- | --- |
| L0 | `difficulty/level0` | 有完整操作指引，能够运行、理解并记录结果 | 准备环境、运行示例、验证文档步骤 |
| L1 | `difficulty/level1` | 范围明确，在导师指导下完成局部修改 | 复现已知问题、修正文档、修改简单示例 |
| L2 | `difficulty/level2` | 独立分析问题、实现修改并完成验证 | 修复驱动缺陷、维护配方、补充功能测试 |
| L3 | `difficulty/level3` | 涉及多个模块，需要设计方案并分析兼容性或性能影响 | 定位复杂并发问题、实现跨模块功能 |
| L4 | `difficulty/level4` | 涉及子系统设计、长期兼容性和多方维护协调 | 子系统重构、跨版本迁移、维护策略设计 |

典型任务用于说明能力要求，实际难度由导师根据具体范围判定。导师结合问题的不确定性、涉及范围、验证要求和协作要求，在任务正文记录判定依据、所需知识、设备和指导条件。

- 难度标签用于 `kind/task`。开放申领前由导师确认等级，维护者设置一个难度标签。
- 提议者在任务表单中选择建议等级，或选择“待导师评定”。下拉选择保存为正文，由维护者添加标签。
- 首次验收前，任务范围发生变化时由导师重新评定，维护者更新难度标签。Bot 在首次验收时保存任务记录，后续验收与结算要求难度和年度标签与记录一致；新的独立交付范围使用新任务记录。
- 参与者可以申请高于当前贡献者等级的任务，由导师结合其经验和可提供的指导确认。
